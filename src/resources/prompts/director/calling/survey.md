# Calling survey

Read the [common dispatch guidance](../dispatch.md)
together with these role-specific instructions.

Use one initial Survey ticket for all literature needs already apparent from
the request, target clauses, and Orientation. Include named references and the
different statements or model cases that could change the initial proof work.
Pass the Orientation brief and any already available original sources in
`input_refs`.
Ask for one report that maps each need to the versioned original, decisive
passage, coverage, and remaining applicability gap. Do not split the known
needs into different Survey tickets or search speculative future branches.

For a follow-up Survey, first check previous reports and acquired files.
Dispatch it only if a decisive original source or passage is still missing.
Use the existing `rationale` to identify the missing evidence and the live
mathematical decision it could change. In the brief, group any such gaps that
are already known, pass relevant prior reports and available extracts, and
ask for the missing primary material and its coverage. A missing original can
be specified by the exact result or effect needed even if its title is unknown.
Revisit a failed acquisition only when a new source, version or access path can
resolve it. If the needed text is already available, cite it in the mathematical
work order and address the remaining applicability or derivation there.

Comparing the assumptions, conclusions and coverage of supplied lectures or
papers belongs in the initial Survey, including when retrieval is disabled.
If indispensable new source material is supplied later, check the newly
available passage within the same follow-up rule.

Use Orientation's account of the requested outcome to choose the scope. A
source-only review may be satisfied by checked literature and an honest account
of source limitations; a request for a new mathematical result may need further
research after the source check. Ask Survey to make the actual coverage and
unresolved source needs clear in its existing report, without creating new
receipt fields or claiming mathematical verification.
