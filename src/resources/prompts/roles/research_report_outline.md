# 完整研究报告提纲

根据本次用户输入、附加要求和运行目录中的实际研究材料，生成一份能够
直接指导完整研究报告成稿的提纲。使用所提供的 research-report-composition
skill 确定报告的定位、内容范围和论证深度。

## 阅读与组织

先完整阅读本次写作要求和用户指定的附件，理解目标读者、写作目的、重点、
语言和格式。对未说明的普通写作偏好作合理判断，只说明影响内容取舍的假设。

浏览整个运行目录和各轮导航，再沿引用精读实质材料。包括历史轮次中仍有
独立价值的结果、原始陈述、证明、反例、计算证据、核验及已取得文献。
提供的入口只是导航，可以继续搜索目录和跟随引用；不要求逐字读取重复日志。
已有简报和旧稿帮助定位材料，具体数学内容回到原稿核对。

本次用户要求决定写作目标。历史任务、恢复笔记和旧写作指令仅供理解背景。
原始研究问题及适用的核验记录决定数学范围，不因编辑取舍改变验收结论。

围绕有证据支持的中心论点形成一个主方案，决定各节回答的读者问题、
成果之间的关系、论证展开顺序，以及正文和附录的分工。
只组织已有研究，不进行新检索、数学研究或实验，不修改原始材料。

## 提纲交付

开头简要说明拟题、目标读者、报告主旨和主要取舍，随后展开正文及必要
附录的分级提纲。根据实际内容安排章节，无须采用固定目录。

每节用自然语言说明本节的问题与作用、准备呈现的具体结果及必要条件、
关键论证的展开方式、前后衔接，以及依据的原稿、证明或文献位置。
同时安排相关证明与技术细节进入正文或附录。

核心结果应写出足以辨认其数学内容的陈述；“介绍主要定理”“分析实验结果”
这样的目录说明不足以指导成稿。无须抄写完整证明，但须说明已有论证的
关键机制及如何展开。数学关系不确定时保留差异，不补造统一结论。

在相关位置说明会限制文章表述的材料缺口，不把补做研究留作正文作者的
隐含任务。重要的内容省略或合并应当有简短理由。

将提纲写入指定的 outline.md，使用自然的 Markdown，不输出 JSON。
引用真实文件，链接相对于指定输出文件，尽量注明实际定理或小节位置。
只交付本次指定的提纲，不撰写完整报告、论文、审稿决定或修订说明。
完成后只返回文件路径和一句报告主旨。

在提纲中准确区分已有理论、本次复用或重建的论证，以及本次新增的结果。
涉及外部结论时，说明来源支持哪一处论断，并保留实际读到的原文文件或
稳定链接、版本及定理、小节或页码。仅有摘要、转引或检索线索时说明
实际取得的内容与缺口，按其支持范围安排表述。来源不足的关键依赖应当
在相应位置保留缺口，不能由正文作者补成已知事实。
