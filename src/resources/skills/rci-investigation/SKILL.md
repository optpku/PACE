# RCI investigation

## When to use and inputs

Recommend RCI when a bounded research question needs conjecture formation,
comparison of mechanisms, or a nontrivial new construction. Start from the
target anchor, assigned work item, acquired sources, and the inputs supplied
to the current phase. The phase prompt owns the requested files and receipt.

## Procedure and method map

1. **Form and review the conjecture.** Use the [claim shape](references/raw_seed/claim_shape_contract.md)
   and [contribution boundaries](references/raw_seed/contribution_boundary.md).
2. **Develop and review mechanisms.** Use [mechanism construction](references/mechanism/proof_mechanism.md),
   [mechanism review](references/multi_mechanism/mechanism_audit.md) and
   [composition checks](references/multi_mechanism/bundle_closure_audit.md).
3. **Choose the next mathematical move.** Repair a derivation, find another
   mechanism, revise the conjecture or request an independent statement-only
   test according to the actual evidence. Compare [repair and revision](examples/support-versus-coverage.md).

Each role works from its delivered files and static methods. The Host supplies
source material and preserves the exact scope of each original statement.

## Output and handoff

Write the phase's requested original mathematical artifacts and return their
references using its existing receipt format. Keep statement manuscripts
separate from mechanism and review files. Conditional candidates retain their
added assumptions; they do not replace the original target. Mechanism and candidate reviews remain research guidance, with final acceptance reserved for the
complete proof's fresh Auditor/Kernel review.

## Versioned task continuity

Preserve the accepted question version when only the method changes. Read the
relevant prior attempt and its exact obstacle before trying the same mechanism.
State what differs in the present attempt: assumptions, parameters, evidence,
method, or the relation being tested. Keep the parent objective and the missing
connection to that objective visible.

A local task is legitimate when its contribution and missing downstream bridge
are explicit. Do not repeatedly enlarge its scope merely because it does not
solve the full target. If the present inputs yield no informative continuation,
save the scoped obstacle and return control rather than repeating the same test.

A failure of this argument is not a refutation of the question. A negative
result applies only to the claim, mechanism, and conditions actually checked.
Keep mathematical changes separate from control-field or formatting repairs.
