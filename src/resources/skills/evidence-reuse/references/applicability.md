# Review the application, not just the citation

Write the source statement as \(H_{old}(u)\Rightarrow C_{old}(u)\).
For the proposed substitution \(u=\phi(v)\), there are two distinct obligations:
\[
H_{new}(v)\Rightarrow H_{old}(\phi(v)),\qquad
C_{old}(\phi(v))\Rightarrow C_{needed}(v).
\]
The second implication may also use explicitly established current premises.
State them. A notation map alone proves neither obligation.

Read the original proof when a bound hides dependencies needed by the new
application. For example, \(C=C(d,R)\) cannot become a universal constant by
renaming it. Likewise, a bound on some admissible subgradient cannot be assigned
to the particular subgradient selected by a later optimality condition.

Check the provenance separately: which statement version was reviewed, under
which assumptions, with which unresolved obligations? Use the exact artifact,
not a recollection in a summary. This review provides a scoped premise for the
mathematical argument; it does not modify Host acceptance records.

When a condition changes, inspect applications that consume it. Preserve
unaffected findings at their proved scope. For affected uses, give the missing
bridge and its consumers in ordinary prose, with actual file references in the
assigned memory note. Do not invent a new graph database or status format.

If an application fails, retain its concrete obstruction. Later attempts can
test a new substitution or weaker sufficient conclusion without repeating a
refuted transfer. Whole-proof review still checks the assembled argument.
