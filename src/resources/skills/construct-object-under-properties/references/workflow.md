# Construct Object under Properties

# Input Contract

- Read the exact target, condition profile, construction blueprint, and required properties.
- Read construction certificates and capsules only within their recorded conditions.
- Keep the object type explicit: function, witness, sequence, potential, or hard instance.
- Record the ambient space, norm or topology, dual pairing, and object-membership requirements.
- Treat a verified obstruction as a constraint on redesign, not as proof of a new object.
- Treat an incomplete construction as unresolved rather than mathematically false.
- For Research, construct only the requested local object or property.

# Procedure

1. List every required property and its role in the downstream proof.
2. Separate defining data from properties that still require proof.
3. Give an explicit formula, recurrence, selection rule, or finite construction.
4. Specify the domain, codomain, dimension, horizon, indices, and parameter ranges.
5. For a set-valued map or relation, define its graph, values, domain, codomain, and every operation applied to it.
6. For a graph comparison, give one primal point and prove each required graph membership there; do not infer graph membership from averaging, scaling, interpolation, or closure without a preservation theorem.
7. Prove the construction exists, is well defined, and lies in the required ambient class before using its consequences.
8. Name the topology for interior, closure, compactness, continuity, or lower semicontinuity claims and prove the required qualification in that topology.
9. For a net, sequence, or subnet, state its directed set and componentwise convergence, and prove any uniform norm bound separately from convergence.
10. For a recovered limit object, prove the exact closedness or selection bridge that returns it to the required graph or feasible set.
11. For a function, verify regularity, convexity or curvature, growth, and normalization as required.
12. For a witness, verify every membership and admissibility property before computing the target quantity it controls.
13. For an auxiliary sequence, give initialization, recurrence, index range, and closed consequences.
14. For a potential, define every term and prove base, one-step, and terminal relations separately.
15. For a hard instance, specify dimension or horizon and verify full class membership.
16. For a hard instance, verify oracle legality and the permitted method transcript.
17. Treat deterministic, randomized, linear-span, and arbitrary-method scopes distinctly.
18. For randomized claims, state distributions, coupling, expectation, and confidence explicitly.
19. Derive the final violation, lower bound, or rate inversion from the constructed object.
20. If the construction must defeat a strict margin, quantify its residual against that margin rather than citing asymptotic closeness alone.
21. Check constants, scaling, boundary cases, and nondegeneracy conditions.
22. Verify each property independently; do not infer all properties from a plausible formula.
23. Insert the completed construction into the target's dependency chain.

# Role-Specific Use

- Prover must include the definition and every required property proof in one complete proof.
- Research returns one insertable construction or an honest inconclusive candidate.

# Handoff and Failure Discipline

- Hand off a remaining local identity to direct gap closure.
- Hand off a parameter or extremal uncertainty to boundary exploration or bound refinement.
- Hand off an algorithmic object with a success contract to algorithm construction.
- If an ansatz is refuted, change a substantive formula, recurrence, or structural ingredient.
- If only one property fails, preserve independently verified properties with their conditions.
- Do not use code, finite tests, or a construction sketch as proof of universal properties.
- Do not infer theorem-level refutation from failure to synthesize an object.
- Final authority comes only from the complete proof and ordinary fresh verification.
